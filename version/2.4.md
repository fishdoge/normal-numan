# 凡人修仙傳 — 版本 2.4

發布日期:2026-08-24

小變動:修復宗門倉庫「存入」功能 100% 必定失敗且無任何錯誤提示的問題。

## 修復:宗門倉庫存入功能完全失效

- **根因**:`depositItem` 的 SQL 用 `jsonb_build_object(${itemId}, ${qty})` 直接把參數傳給多型(polymorphic)函式,Postgres 無法推斷裸參數型別,丟出 `NeonDbError: could not determine data type of parameter $8`,整支請求 500——與先前修過的 `to_jsonb(${變數})` 是同一類問題的另一種寫法,一樣需要顯式轉型才能解。補上 `${itemId}::text, ${qty}::int` 後恢復正常。
- **連帶發現的靜默失敗**:`SectPage.tsx` 的共用 `post()` 函式在 `res.json()` 前沒有防呆——伺服器丟出未捕捉例外時,Next.js 預設回應不是 JSON,`res.json()` 直接拋出例外且沒有 catch,導致整個動作「看起來什麼事都沒發生」,不會顯示任何錯誤訊息。這是這次「怪怪的」回報的直接體感來源:點了存入,沒反應,也不知道為什麼。現在補上 try/catch,伺服器錯誤一律會顯示訊息(非 JSON 回應時退回通用錯誤字串,網路徹底斷線時顯示連線錯誤),不會再悄無聲息。
- **實測驗證**:用測試帳號存入/提領道具皆確認正常——存入後個人儲物袋下拉選單即時反映剩餘數量(數量歸零時下拉正確跳回「選擇物品…」預留位置,而非停在已消失的選項上),提領後倉庫與個人儲物袋數量同步正確增減。

## 技術細節

- `src/app/api/sect/route.ts`:`jsonb_build_object` 呼叫補上顯式型別轉換。
- `src/components/SectPage.tsx`:`post()` 函式的 `res.json()` 改用內層 try/catch 包住(解析失敗時退回通用錯誤訊息),外層新增 catch 處理網路層例外(顯示 `netErr` 連線錯誤文案),兩者皆確保 `busy` 狀態經由 `finally` 正確清除。
