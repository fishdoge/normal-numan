# 凡人修仙傳 — 版本 3.16

發布日期:2026-09-21

延續 3.15 版的兩個實測回饋:符寶袋的擁有份數制改為溯及既往(直接砍掉舊存檔的超額張數,避免影響遊戲平衡);傷害畫面加大加華麗,並新增怪物受擊震動。

## 符寶袋擁有份數制:改為溯及既往

3.15 版上線時,考量到「玩家一登入符寶突然消失」的觀感,刻意讓已經設定好的符寶袋維持原狀,只節制「之後想再多放」的新增動作。但這會讓上線前就已經超額複製符寶的舊存檔,在數值上持續領先於新規則下組出的符寶袋,影響遊戲平衡——這次修正為主動砍除:

- 每個存檔第一次執行任何動作時,自動檢查符寶袋裡每門仙法的張數,超過目前擁有份數(預設 1 份,基礎卡片不受影響)的部分直接砍除。
- 只會執行一次(存檔會記下已經修正過),不會每次都重新檢查,也不會影響到修正之後玩家自己複製出來的新符寶。
- 純粹刪減,不會補償任何資源——如果覺得損失的符寶份數想要補回來,一樣是透過「複製符寶」(對已學會的秘笈重新參悟)取得。

## 傷害畫面加大加華麗

- 傷害數字整體加大(原本統一 2xl,現在一般傷害提升到 3xl);命中五行相剋時進一步放大到 4xl,並在數字後方多一圈依屬性上色的爆閃光暈;被剋制則縮小示弱(xl),三種份量一眼可以分辨。
- 數字的進場動畫改成「彈出感」:從縮小帶點傾斜開始,瞬間放大超過原尺寸再回彈定住,比原本單純淡入更有力道。
- 數字發光效果改為依五行屬性動態上色的雙層光暈(取代原本純黑色陰影),法器攻擊等無屬性傷害則沿用金色(對怪物)/硃紅色(對玩家)的發光。

## 新增怪物受擊震動

怪物圖騰每次真的受到傷害,會有一小段左右搖晃 + 些微旋轉的震動(0.4 秒),搭配 3.15 版已有的屬性色光環爆閃,擊中的回饋更明顯。震動只在「伺服器確認真的造成傷害」時觸發,不會因為出牌被閃避而誤觸發。

## 技術細節

- `src/game/engine.ts`:
  - 新增 `SaveData.pouchTrimmed?: boolean` 欄位與 `trimPouchToOwnership()`——依 `ownedCopiesOf()` 砍除符寶袋中每門仙法超過擁有份數的多餘張數,寫入向後相容 hydration 區塊,以 `pouchTrimmed` 旗標確保只執行一次(同一套模式沿用既有的 `boonReset` 慣例)。
- `tailwind.config.ts`:`dmgFloat` keyframe 改為「縮小傾斜 → 放大回彈 → 定住 → 上浮淡出」的彈出式進場,取代原本單純的淡入。
- `src/app/globals.css`:新增 `.battle-sigil-glyph-shake`(怪物圖騰受擊震動,`battleGlyphShake` keyframe)與 `.dmg-float-burst`(克制傷害的爆閃襯底,`dmgBurstPop` keyframe,顏色透過 `--burst-color` 動態決定),兩者皆納入既有的 `prefers-reduced-motion` 例外處理。
- `src/components/panels.tsx`:
  - `DamageFloats` 依 `advantage` 決定字級(super → 4xl + 爆閃襯底,resist → xl,一般 → 3xl),發光顏色改用 `ELEMENT_HEX`/`TONE_HEX` 動態計算的雙層 `textShadow`。
  - `CombatPanel` 新增 `lastMonsterHitId`(取最新一筆對怪物造成傷害的事件 id),以此當作 `.battle-sigil-glyph` 的 React key——每次真的造成傷害就強制重新掛載該節點,讓震動動畫確實重播(單純套用同一個 class 不會自動重播 CSS 動畫)。
- 已撰寫獨立測試腳本,涵蓋舊存檔超額符寶被砍到擁有份數、基礎卡片不受影響、份數足夠時不誤砍、`pouchTrimmed` 旗標確實只執行一次,共 4 組情境、6 項斷言,全數通過;`tsc --noEmit`、`next lint` 皆乾淨無誤;並以既有測試帳號透過真實瀏覽器操作驗證符寶袋回溯修正確實生效(2 張砍到 1 張)、克制傷害的加大字級/爆閃/怪物震動三項特效皆正確觸發。
