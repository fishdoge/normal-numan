# 凡人修仙傳 — 版本 2.9

發布日期:2026-08-26

修正:見聞錄/對話集捲動異常(根因是 `/api/save` 無限重複請求的效能 bug)。

## 根因:`useT()` 未做記憶化,連鎖觸發 `/api/save` 無限迴圈

- **症狀**:玩家反映「見聞錄好像壞掉了」「上下拉動好像又有問題」——手動往上捲想回顧之前的內容時,畫面會被不斷拉回底部,幾乎無法停留在想看的位置。
- **根因**:`useT()`(`src/i18n/useT.ts`)每次呼叫都回傳一個全新的函式參考(未用 `useCallback`/`useMemo` 固定)。`Game.tsx` 的 `loadSave`(`useCallback`,依賴陣列包含 `t`)因此在每次 render 都拿到新的函式參考,導致本身也變成新的參考;而 `useEffect(() => loadSave(), [loadSave])` 的依賴 `loadSave` 每次 render 都不同,於是每個 render 都重新觸發 `loadSave()` → 呼叫 `setSave()` → 觸發重新 render → 又拿到新的 `t` → 又觸發 `loadSave` 變動……形成無限迴圈,實測结果是每秒不斷對 `/api/save` 發出請求,只要遊戲分頁開著就永不停止,平白消耗流量與資料庫查詢。
- **連鎖影響**:每次 `/api/save` 回應都會用全新物件覆蓋 `save`,連帶讓「見聞錄」內容陣列(`save.log`)每次都變成新的參考,即使內容其實沒變。原本的自動捲動邏輯是「`log` 一有變動就無條件捲到底」,因此即使玩家什麼都沒做,畫面也會每秒被強制拉到底部一次,手動往上捲完全留不住。
- **修正**:
  1. `useT()` 改用 `useCallback`(依賴 `language`)回傳穩定的函式參考,徹底解決連鎖無限迴圈的根源;順手排查全站,只有 `Game.tsx` 這處把 `t` 放進依賴陣列,無其他地方有相同風險。
  2. 「見聞錄」與「對話集」的自動捲動邏輯改為「貼底感知」:捲動時即時偵測是否已在底部附近(誤差 40px 內),只有原本就貼底才會在新內容出現時自動捲到底;手動往上捲開之後不會再被強制拉回,切換頁籤或重新切回時視為使用者要看最新內容,才會重新貼底並捲到底部。

## 技術細節

- `src/i18n/useT.ts`:回傳值改為 `useCallback((key) => DICT[language][key], [language])`。
- `src/components/LogChatPanel.tsx`:新增 `logPinnedRef`/`chatPinnedRef` 搭配 `onScroll` 偵測,取代原本無條件的 `useEffect(() => scrollTo(bottom), [log])` / `[messages, tab]`。
