# 凡人修仙傳 — 版本 1.17

發布日期:2026-08-13

付款服務由 Creem 更換為 Polar:「向仙班祈禱 · 六道輪迴盤」付費復活功能改走 Polar API 動態建立結帳工作階段,玩家端行為與 1.16 版完全相同。

## 付款服務更換:Creem → Polar

- 移除 1.16 版的 Creem 靜態付款連結 + metadata 透傳方案,改用官方 `@polar-sh/sdk` 動態建立結帳工作階段(`polar.checkouts.create()`)。
- 改善:Polar 方案可直接指定 `successUrl`(付款完成後自動導回遊戲首頁),不再像 Creem 靜態連結那樣只能依賴商品預設導回頁。
- 以 Polar 回傳的 checkout session id 作為 `revival_requests` 的關聯 token,取代原本自行產生的 UUID。
- Webhook 改監聽 Polar 的 `order.paid` 事件,簽章驗證改用官方 SDK 的 `validateEvent()`(基於 Standard Webhooks 規範),不再手刻 HMAC 比對。
- 復活邏輯本身(`engine.ts` 的 `reviveSave`)、終身僅一次的 `users.revival_used` 旗標、`revival_requests` 冪等狀態機、死亡畫面的輪詢 UI 皆不變——只是觸發付款與驗證付款的底層服務換了。

## 部署前必做設定(取代 1.16 版的 Creem 設定步驟)

1. 至 Polar 後台建立一個 15 USD 的一次性商品,複製其 Product ID,填入環境變數 `POLAR_PRODUCT_ID`。
2. 至 Polar 後台 Settings > Webhooks 新增 webhook,網址填 `https://<你的網域>/api/webhooks/polar`,訂閱 `order.paid` 事件,把顯示出來的 Webhook Secret 填入 `POLAR_WEBHOOK_SECRET`。
3. `POLAR_KEY`(Organization Access Token)已設定;若該 token 是 sandbox 環境核發,需另外把 `POLAR_SERVER` 設為 `sandbox`(預設 `production`)。
4. 以上四個環境變數本機 `.env` 與正式部署平台皆須設定一致。

## 技術細節

- 新增依賴 `@polar-sh/sdk`。
- `src/lib/payments.ts` 改為建立並匯出 Polar 客戶端單例(`polar`)與 `POLAR_PRODUCT_ID`/`REVIVAL_PRICE_USD` 常數。
- `src/app/api/revive/route.ts`(POST)改為呼叫 `polar.checkouts.create()`,以 `checkout.id` 存入 `revival_requests.token`,回傳 `checkout.url` 供前端開新分頁。
- 移除 `src/app/api/webhooks/payments/route.ts`(Creem 專用),新增 `src/app/api/webhooks/polar/route.ts`,以 `@polar-sh/sdk/webhooks` 的 `validateEvent`/`WebhookVerificationError` 驗證簽章,處理 `order.paid` 事件。
- 前端(`Game.tsx` 的 `PrayForRevival`)與 `/api/revive` 的請求/回應格式完全不變,故本次調整無需修改任何前端程式碼。
